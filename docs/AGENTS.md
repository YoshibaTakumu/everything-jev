# Documentation rules

- For development workflow changes, read [dev-policy/](dev-policy/README.md) and its [AGENTS.md](dev-policy/AGENTS.md). Shared document placement and maintenance belong to [document lifecycle](dev-policy/document-lifecycle.md).
- Before editing documentation, use [the index](README.md) to find its owner and follow [documentation maintenance](tech-stack/documentation.md#updating-the-documents). For `tech-stack/`, read the [topic index](tech-stack/README.md) and verify adoption claims against the linked implementation/configuration.
- For concept definitions, relationships and behavioral invariants, use [domain/](domain/README.md) and read its [AGENTS.md](domain/AGENTS.md). New documents use its template and join its index in the same change.
- Before editing `api.md`, `architecture.md`, `security.md` or `harness.md`, read [../.claude/rules/api-policy.md](../.claude/rules/api-policy.md).
- Before editing `evaluation.md`, read [../.claude/rules/testing-evaluation.md](../.claude/rules/testing-evaluation.md).
- Before editing `cookbook.md`, read [../.claude/rules/recipes-docs.md](../.claude/rules/recipes-docs.md).
- Before editing `quality.md`, read [../.claude/rules/tooling-ci.md](../.claude/rules/tooling-ci.md).
- Before editing `tech-stack/`, also read [../.claude/rules/tooling-ci.md](../.claude/rules/tooling-ci.md).
