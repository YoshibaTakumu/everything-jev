---

Issue 群を**依存グラフ**として扱う。辺は GitHub の native な関係（sub-issue、blocked-by、Issue を閉じる PR）だけで、グラフの実体は GitHub が持つ。コメント・本文・記憶・この会話にある状態はすべて**キャッシュ**であり、判断の入力にしない。

## 手順

1. **再取得する。** 親 Issue から、問い合わせをまとめてグラフを取る（[コマンド](references/COMMANDS.md)）。散文にしか無い依存（「#12 の後で」など）を見つけたら、辺の候補として控える。
   - 親が複数なら子孫の和集合を取り、repository と番号で重複を除く。入れ子の子と各接続の続きも取得し、範囲外の blocker は依存の根を辿るために読む。親の包含は blocked-by とは別で、親の blocker を子へ継承しない。親自体の状態は子の集計と分けて示す。
2. **全 Issue を分類する。** 完全に取得できた各 Issue を次の優先順でちょうど1つへ入れる。取得に欠けがある Issue は未確認として分け、フロンティアに数えない。
   - **完了**: closed。
   - **進行中**: assignee がいる、または Issue を閉じる open PR がある。
   - **ブロック**: open の blocker が 1 件以上ある。どの blocker かを名指しする。
   - **フロンティア**: 上のどれでもない。グラフ上で今着手できる。Issue でない前提（判断・承認・日付）は各 Issue の完了条件にあり、分類には入らないので、着手を勧める前にその Issue の完了条件を読む。
   依存の辺を読めない経路では、本文中の依存を暫定の候補として示す。記載が無いことを blocker 不在の証拠にせず、native な辺を読めるまで着手可否は未確認とする。
   循環を見つけたら分類を止め、循環を成す辺を示す。フロンティアが空で完了していない Issue が残るなら、進行中かブロックの根を辿って、誰の何が解ければ進むかを示す。
3. **提示して決定を仰ぐ。** 分類結果と、辺の追加・削除の候補、フロンティア内の推奨着手順を理由付きで示す。可視化を求められたとき、または open の Issue が 8 件を超えるときは[図](references/VISUALIZE.md)で示す。見るだけの依頼で、辺の候補も無ければ、ここで完了。グラフの**事実**を集めるのはエージェントの仕事で、利用者へ尋ねない。辺を足す・外す、フロンティアのどれから着手するかは**決定**で、利用者のものなので、既存の明示的な指示で委ねられていなければ回答を待つ。
4. **決定を native な辺へ書く。** 確定した依存は blocked-by / sub-issue として GitHub へ書き、散文の依存はそれで置き換える（[コマンド](references/COMMANDS.md)。`gh` の版で経路が分かれる）。次のエージェントが再取得だけで同じグラフへ辿り着けることが目的。
   - **依存の辺を書けない経路**では、実際に対応している操作だけを行い、未実行の辺を一覧にする。実行できるコマンドと必要な権限を示し、書き込み済みとは扱わない。手順6の照合は、辺が入った後に行う。ツール名だけから読み書きの可否を決めない。
5. **投稿が依頼されている場合に残余だけを親 Issue へ記録する。** 投稿の指定が無ければ現在の会話へ報告する。コメントへ書くのは GitHub から再取得できないもの、つまり着手順の理由、辺を足した・外した理由、保留した判断とその解消条件。分類表や状態の一覧は書かない（再取得すれば得られ、書いた瞬間から古くなる）。
6. **照合する。** 同じ経路で再取得し、書いた辺と、投稿した場合はコメントが送信した内容と一致することを確かめる。一致して、全 Issue が分類済みで、確定した依存がすべて native な辺になっていれば完了。

## コメントの書き方

GitHub は `#番号`・`owner/repo#番号`・Issue / PR の URL をタイトルへ自動展開し、番号の多い記録を読めなくする。コードスパンの中は展開されない。

- 本文中の番号はコードスパンで書く（`` `#12` ``）。辿るための実リンクは末尾の `### 参考` 節へ 1 行 1 リンクで集める。
- GitHub や道具が機械的に読む参照は生のまま残す。PR 本文の `Closes #番号` が該当する。
