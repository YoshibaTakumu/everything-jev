監視は**観測と報告**である。実装を進める役は [draining-frontier](../draining-frontier/SKILL.md)、依存の分類は [sequencing-issues](../sequencing-issues/SKILL.md) が持つ。監視だけの依頼では、Issue・依存・担当・PR・実行中のセッションを変更しない。実装も依頼されている場合は、その既存の権限を持つ本体へ結果を渡す。

この手順は 1 回の観測で完了する。作業中は波の区切りで呼び、会話が動いていない間の定期監視は別途、実行環境のスケジュール機能で起動する必要がある。スキルの整備だけを求められたときは定期実行を登録しない。監視頻度・報告先・終了条件を含む実際の登録を確認できるまで「監視中」と伝えない。

## 手順

1. **範囲と比較元を決める。** 指定された親 Issue 全件とその子孫を対象とし、重複は repository と Issue 番号で除く。指定が無ければ会話の対象範囲を使い、それも無ければ範囲だけ尋ねる。親を追加して探索範囲を広げる判断は利用者に返す。範囲外の blocker は原因を読むために取得し、完了件数には含めない。
   - 前回の報告または作業用の観測記録を比較元にする。これは差分通知のためのキャッシュで、現在の判断には手順 2 の取得結果を使う。
   - 完了: repository・親の一覧・比較元の観測時刻が分かる。比較元が無ければ初回観測とする。
2. **現在を読む。** sequencing-issues の取得・分類を行う。取得経路と PR の状態・検査・レビューは [コマンド](../sequencing-issues/references/COMMANDS.md#監視の読み取り) に従う。担当する実行の記録は、利用可能な実行環境の読み取り機能で確認する。Issue・branch・revision と実行記録の対応を確認できない場合は、対応が未確認であると示す。
   - 各接続の続きを含め、closed の子も取得する。前回あった Issue が今回の一覧に無ければ個別に読み、close・親からの除外・取得不能を区別する。open 一覧から消えたことだけで完了にしない。
   - 親の包含関係と blocked-by を区別する。親の blocker を子へ自動で継承しない。子を持つ Issue は集約として別に表示し、完了率は重複を除いた末端 Issue の closed / 全件とする。子が全部 closed でも親を自動で閉じない。
   - Issue のグラフ分類と、作業の決定待ち・入力待ちは別に持つ。フロンティアであることだけで着手可能とは報告せず、本文・新しいコメント・利用可能な実行記録で理由を確かめる。
   - 読めない項目は「未確認」とする。前回の値を使うときはその観測時刻を添え、取得失敗を「変化なし」「完了」に置き換えない。一部だけ読めたときは、読めた範囲の報告を続ける。対象の Issue・PR・revision に結び付けられない実行報告は、個別の完了や検証成功の根拠にしない。
   - 完了: 各範囲の取得時刻・取得の欠け・グラフ分類・実行上の保留が根拠へ辿れる。
3. **変化と止まった理由を照合する。** 初回は現在地を報告する。2 回目からは下の表で、前回との差分を求める。記録の更新が無いことと、プロセスの失敗は別である。

   | 観測 | 報告すること |
   |---|---|
   | Issue の close・reopen、PR の merge・非 merge close | 対象のリンクと状態の変化。merge と Issue の close は個別に確認する |
   | blocker の解消・追加、担当・関連 PR の変化 | 新しいフロンティア、再ブロック、誰の何を待つか |
   | 検査の失敗・回復、レビューの変更要求 | 現在の PR の head に対応する根拠と、後続への影響。検査なし・実行中・未取得を成功に数えない |
   | 決定・入力・レビュー待ち | 求める回答や入力、根拠、解消すると進む Issue。秘密は値でなく置き場の path を尋ねる |
   | 動きが見えない | 最後に確認できた活動と経過時間。停滞の閾値が指定されていれば候補として挙げ、未指定なら「更新を観測できていない」とする |
   | 取得不能・復旧 | 何が見えないか、最後に確認できた時刻。復旧時は最後の正常観測との差分を取る |
   | 範囲内の子の追加・除外 | 件数の分母の変化。除外を完了に数えない |

   - 同じ Issue に複数の実行が対応するときは、重複作業の疑いとして契約・branch を確認し、本体へ渡す。監視役が片方を停止したり、PR を merge したりしない。
   - 完了: 各報告候補に前回と今回の根拠がある。初回・比較不能は差分と区別されている。
4. **利用者へ報告する。** 既定の宛先は現在の会話。外部への投稿は、利用者が宛先と投稿を指定した場合だけ行い、利用可能な投稿ツールで送信結果を照合する。本文は次の順で、該当する項目だけ短く書く。
   - **判断が必要**: Issue、止まった理由、問い、選択肢と推奨。既に回答された問いは繰り返さない。
   - **前回からの変化**: 完了・進行・失敗・回復とリンク。実行していない検査は未実行と書く。
   - **範囲ごとの現在地**: 親、末端の closed / 全件、進行中、ブロック、フロンティア、実行上の保留。保留はグラフ分類の内訳で、件数へ重ねて足さない。
   - **次に進めること**: 新しく解放された Issue と、残るブロックの根。実装を依頼されていなければ提案に留める。
   - **時間の見通し**: drain の見積もり記録があれば、初期予測・実際の経過・残り時間の範囲・更新理由を添える。Issue の完了率から残り時間を比例計算せず、[時間の見積もりと実績](../draining-frontier/references/ESTIMATION.md) の残工程を使う。記録が無ければ未計測とし、監視だけで実装や計測用の重い処理を起動しない。
   - **観測の限界**: 取得時刻と未確認の範囲。セッション終了だけで Issue の完了や検証成功を断定しない。
   - 完了: 利用者が必要な判断と次の進捗を、リンク先の根拠から確かめられる。
5. **比較元と報告済みの記録を残す。** 会話の報告、または gitignored な `local/` など次回も読める作業用の保存先へ、範囲・観測時刻・対象ごとの状態と根拠・未確認・保留・実際に報告できた差分を残す。秘密やログ全文は保存しない。保存先は作業の記録として扱い、製品コードや恒久仕様へ混ぜない。
   - 比較元は Issue 全体で一括更新せず、状態・包含関係・依存・PR の head・検査結果ごとに観測時刻を持ち、完全に取得できた項目だけ進める。取得に失敗した項目の最後の正常観測は残す。報告に失敗した差分は未報告として次回へ引き継ぎ、新しい観測との差分が空でも報告候補に残す。送信結果が不明なら届いたか照合してから再送する。
   - 同じ事象・同じ状態・同じ根拠の報告は繰り返さない。失敗→回復→再失敗は別の変化とする。判断待ちは一覧に残し、新しい根拠・期限・回答がある場合だけ再び強調する。
   - 明示的に現在地を聞かれたら変化がなくても回答する。反復監視で変化がなければ通知を省き、正常に観測した時刻だけ残す。実行環境が無通知の終了を扱えなければ、その限界を示して最短の「変化なし」を返す。
   - 全件 closed でも観測に欠けがあれば完了扱いにしない。親の未完了条件も確認し、定期実行の終了は登録済みの終了条件に従う。全件が人間待ちであることは完了ではない。
   - 完了: 次回が比較元と報告済みの差分を区別できる。保存先を引き継げない環境では重複抑止を保証せず、次回を初回観測とする。
