Jev を、与えられた state に対する限定された意味判断を返すモデルとして説明する。コードが候補・計算・制御・実行を担当し、Jev は Choice・Score・Noul を返す。型が合うことと判断が正しいことを区別する。

これは `everything-jev` の独自ガイドで、TypeSafe の公式スキルではない。公式資料は **2026-09-22** に確認した。変わり得る仕様は回答・実装時に公式ページで再確認する。

## 説明・設計の進め方

1. **判断の単位を決める。** 入力、必要な出力、後続の操作を整理する。概要の質問にはそのまま説明し、設計に必要な情報だけ補う。
2. **コードで確定できる部分を分ける。** 計算、検索範囲、アクセス権、依存グラフ、候補ID、外部書き込みをコード側へ置く。残る意味判断に Jev が必要か判断する。
3. **小さな質問へ分解する。** 1質問1判断にし、共通 state で独立して答えられる質問はまとめる。前の回答が必要な段階は別リクエストに分ける。
4. **結果の扱いを決める。** 候補外・情報不足・低確信の扱いと、決定論的な検証、再確認・人間への引き継ぎを設計する。しきい値は用途の評価データから決める。
5. **根拠と検証範囲を添える。** 公式仕様、公式の実験結果、このリポジトリの実装、設計上の推奨、自分で測った結果を分ける。採用案には対象 workload での比較方法も示す。

## 回答と実装の境界

- 現行モデル、価格、上限、SDK の名前・メソッドは公式の Models・API・SDK ページで確認する。確認できない場合は確認日と未確認点を伝える。
- 公式 cookbook の速度・コスト・精度を、別のデータやこのリポジトリでの実績として扱わない。既存デモは架空の固定応答で、ライブ品質の評価ではない。
- セットアップ説明やスキル作成だけの依頼で、課金される推論、資格情報の取得、外部操作、追加スキルのインストールを開始しない。実行も依頼されていれば既存の権限内で進める。
- 最終的に、Jev が担当する判断、コードが担当する処理、適する理由、残る弱点、次の検証、公式の参照先が分かる形で返す。
